# ESP32（ST7789 240×240）使用说明

## 硬件接口一览

> 本表按**当前代码实际使用情况**核对（V1.6.7）。
> 屏幕驱动与 SPI 引脚在 Arduino 库目录的 `TFT_eSPI/User_Setup.h` 里，其余引脚全部在 `SmallDesktopDisplay.ino` 内定义。

### 1. 显示屏 ST7789 240×240（SPI）

| 信号 | GPIO | 方向 | 配置位置 |
|---|---|---|---|
| MOSI | **23** | SPI 数据输出 | `User_Setup.h` |
| SCLK | **18** | SPI 时钟 | `User_Setup.h` |
| CS | **5** | 片选输出 | `User_Setup.h` |
| DC | **27** | 数据/命令 | `User_Setup.h` |
| RST | **4** | 复位输出 | `User_Setup.h` |
| MISO | — | **未使用** | 库内默认 `-1`（只写不读，不接） |
| 背光 BLK | **33** | LEDC PWM | `SmallDesktopDisplay.ino` |

- 驱动：`ST7789_DRIVER`（完整配置），SPI 频率 27 MHz
- ⚠️ **GPIO5 已被 TFT_CS 占用，不能再作它用**
- **背光**：`BLK` 直连 **GPIO33**，**高电平点亮**（正逻辑）。PWM 5 kHz / 10 bit，占空比 = 亮度百分比；100% 时 GPIO 恒高 3.3V，与原来直连 3.3V 效果一致。
  - ⚠️ 直驱时 GPIO 要供出背光 LED 的全部电流（ESP32 单脚推荐 ≤ 12 mA、上限 40 mA）。若亮度明显不如直连 3.3V、或 ESP32 发热/复位，请串 33~68 Ω 限流电阻，或改用 P-MOSFET 高边开关（此时网页「背光极性」改选**低电平点亮**）。
  - ⚠️ **背光引脚只在固件里定义**（`LCD_BL_PIN_DEFAULT`），**不要**再往任何 `User_Setup.h` 里加 `#define TFT_BL`；更**绝不能**定义 `TFT_BACKLIGHT_ON`（那会让 TFT_eSPI 在 `begin()` 里抢走该脚，变成"只能全亮或全灭"）。

### 2. I2C 总线（两个设备共用）

| 信号 | GPIO | 说明 |
|---|---|---|
| SDA | **21** | 数据 |
| SCL | **22** | 时钟 |

- 总线速率：**400 kHz**（`Wire.setClock(400000)`）
- **DHT30 / SHT30 温湿度传感器**：地址 **`0x44`**（ADDR 脚接 GND；接 VCC 则为 `0x45`）
- **0.96" SSD1306 OLED**（游戏时长显示）：地址 **`0x3C`**，128×64，驱动用工程内自带的 `oled.h`（无外部库依赖）
- 两者共总线不冲突（地址不同），都接 3.3V / GND

### 3. 触摸 / 其他 IO

| 功能 | GPIO | 模式 | 说明 |
|---|---|---|---|
| TTP223 触摸 SIG | **25** | 输入 + 内部下拉 | 高电平有效，防抖 300 ms；单击循环切换背景图 |

- TTP223 模块的 `A` 焊盘**不焊**（保持出厂「直接输出」模式）；VCC=3.3V，GND=GND

### 4. 网络接口

| 项 | 值 |
|---|---|
| WiFi 模式 | STA（DHCP）＋ WiFiManager 配网门户（首次未配网时开热点 `AutoConnectAP`，无密码） |
| mDNS 名 | **`SD3`** → `http://sd3.local` |
| 固定 IP（已启用） | **`192.168.5.86`** / 网关·DNS1 `192.168.5.1` / 掩码 `255.255.255.0` / DNS2 `114.114.114.114` |
| HTTP | **80** 端口（WebServer，后台页面 + `/dbg` 诊断页） |
| UDP **5005** | 游戏时长接收（电脑端 `game-uptime` → ESP32） |
| UDP **8000** | NTP 校时本地端口（向 `ntp6.aliyun.com:123` 请求应答），东八区 |
| 天气 | `d1.weather.com.cn`，默认城市代码 `101250101`（长沙），可网页改 |

> 固定 IP 是 `192.168.5.x` 网段。若换到别的网段，进配网门户前固件会自动切回 DHCP，不会连不上。
> **断网后会自动按 1→2→4→…→60 秒退避重连，且不会清除已保存的 WiFi 密码**（见 V1.6.8）。
> 屏幕右上角出现红色「无网络」角标即代表当前没连上；恢复后角标自动消失。配网入口有三个：
> 网页「重新配网」/「忘记网络」、串口命令 `0x06`（断网时网页打不开，用这个）。

### 5. 存储

| 项 | 容量 | 用途 |
|---|---|---|
| SPIFFS | 1 MB（huge_app 分区） | 最多 **5 张** 240×240 JPEG 背景图（`/bg0.jpg`~`/bg4.jpg`） |
| EEPROM | 1024 B（NVS 后端） | 配色、亮度、背光极性、每壁纸预设、自动循环等；已用到地址 246，余 778 |

### 6. 不用碰的引脚

| GPIO | 原因 |
|---|---|
| 6 / 7 / 8 / 9 / 10 / 11 | SPI Flash，**绝对不可用** |
| 1 / 3 | 串口 TX/RX（115200 调试） |
| 0 / 2 / 12 / 15 | strapping 脚，上电电平影响启动模式，尽量避开 |
| 34 / 35 / 36 / 37 / 38 / 39 | 仅输入，无内部上下拉 |

## V1.5 新功能

### 1. 文字配色（网页设置）

| 项目 | 可选值 | 说明 |
|---|---|---|
| 小时数字 | **任意颜色** | 大号数字为预渲染 JPEG 字模，固件在解码回调中按亮度重映射到目标色 |
| 分钟数字 | **任意颜色** | 同上 |
| 秒钟数字 | **任意颜色** | 同上 |
| 日期 / 城市 / 滚动条 | 任意颜色 | 取色器选择 |
| 室内温湿度 | 任意颜色 | 取色器选择 |

> **V1.5.1**：时钟时分秒三组颜色改为**完全独立可调**，且支持任意颜色。
> 原理是「动态着色（tinting）」——字模实际是白色 JPEG，解码后逐像素取亮度
> `lum = (R×30 + G×59 + B×11) / 100`，再输出 `目标色 × lum / 255`。
> 这样纯白像素精确映射为目标色，抗锯齿边缘按比例衰减，背景透明区域（纯黑）保持透明。

### 2. 背景图（网页上传，最多 5 张）

- 网页端选择槽位上传图片，**支持 JPG / PNG / WebP 等任意常见格式**，无需自行处理尺寸。
- 上传前浏览器会**本地自动裁剪 + 压缩**（见下方 V1.5.2 说明），最终存为 240×240 JPEG，单张不超过 64KB。
- 图片保存在 SPIFFS 文件系统（`/bg0.jpg` ~ `/bg4.jpg`），**重启后保留**。
- 上传后自动应用为当前背景；点击缩略图可切换；点 `×` 删除。
- **背景暗化滑块**（0-100%）：调节背景亮度，避免亮图盖过文字。0% 为纯黑，100% 为原图。

### 3. 触摸切换背景图

上电后单击 TTP223 模块，在所有**已上传**的背景图之间循环切换（自动跳过空槽位），当前选择写入 EEPROM 持久保存。

### 4. 网页 UI

暗色卡片式界面，天气更新间隔 / 背景暗化均为滑块，配色为**基础色块 + 自定义取色器**，屏幕方向与传感器开关为分段按钮。

**访问地址**：`http://192.168.5.86`（V1.5.5 起固件已固定为该 IP）或 `http://sd3.local`。

> **V1.5.1**：**已移除亮度滑块**。本屏背光在硬件上直连 3.3V，未接 ESP32 控制线（`User_Setup.h` 中未定义 `TFT_BL`），因此软件调亮度物理上无通道，滑块无效。网页改为显示提示文案。

### 5. 分区方案要求

由于背景图功能需要 SPIFFS，且固件体积增长，请在 Arduino IDE 中把 **Partition Scheme 设为 `Huge APP (3MB No OTA/1MB SPIFFS)`**（当前固件占用约 42% / 3MB，SPIFFS 1MB 用于存放背景图）。

> 首次上传固件后若 SPIFFS 为空，背景显示为纯黑，属正常现象；网页上传图片后即生效。

## V1.6.8 修复：断网后不会自动重连（会丢 WiFi 密码）+ OLED 今日总时长

### 现象

WiFi 断开（或开机时路由器还没起来）之后，**网络恢复了也连不回去**，屏幕一直卡在
「Connecting to WiFi......」/「WiFi Connect Fail!」页面，网页后台也打不开。

### 根因（三条叠加，第一条最致命）

| # | 位置 | 机制 |
|---|---|---|
| 1 | `Webconfig()` 里**无条件 `wm.resetSettings()`** | 开机若连不上，约 5.6 秒（194 步 × 30ms 进度条）后就把**已保存的 WiFi 账号密码擦掉**再进 AP 门户。**一次瞬时断网 = 凭据永久丢失**，之后网络恢复也连不回来 |
| 2 | `while(!res);` | `wm.autoConnect()` 返回 false 就**无限空转**：不重试、不超时、不退出，**永远走不到 `Web_Sever_Init()`** → `sd3.local` / `192.168.5.86` 全部打不开。这就是"卡在等待网络连接页面"的直接原因 |
| 3 | `loop()` 里没有任何重连逻辑 | 运行中掉线后无人处理（grep `setAutoReconnect`/`WiFi.reconnect` 零命中） |

附带两处：`Web_Sever_Init()` 里 mDNS 30 秒起不来就 `ESP.restart()`（易成重启循环）；
路由注册与 mDNS 混在同一函数，重连后重复调用会重复注册 handler。

### 修复

1. **彻底不清凭据**。`Webconfig()` 里删掉 `resetSettings()` 与前置 `delay(3000)`；
   WiFiManager 门户本来就支持直接填新 SSID/密码，不需要先擦旧密码。
   真正"忘记网络"改由**显式操作**触发：网页「忘记网络」按钮 / 串口 `0x05`。
2. **新增非阻塞状态机 `wifiTask()`**（loop 每轮调用）：
   - 断开 → 按 **1→2→4→8…→60 秒**退避重连，每轮 `WiFi.disconnect(false,false)` + `WiFi.begin()`
   - 恢复 → 重建 mDNS、`UpdateWeater_en=1` 立刻补拉天气、强制重绘时钟
   - 从未配过网（SSID 为空）→ 才自动进配网门户
3. **开机连接改为有上限**：`setup()` 里最多等 8 秒 / 进度条走完就先进主循环，
   由状态机续连。屏幕正常画出界面，右上角显示红色「无网络」角标。
4. **配网门户带超时**：`wm.setConfigPortalTimeout(180)`，去掉 `while(!res)`。
   三个入口：网页「重新配网」`/wificonfig`、网页「忘记网络」`/wififorget`、**串口 `0x06`**
   （断网时网页打不开，串口是唯一通道）。
5. **拆开 `webRoutesInit()`（只跑一次）与 `netUp()`（幂等，重连后重跑 mDNS）**；
   mDNS 失败只记日志，不再重启设备。
6. **断网角标**：只用线条画（红圈+斜杠）在右上角 `(222..239, 0..15)`，不填色块，
   不会又变成"黑框"。位置独立计时，**不挂在时钟刷新里**——断网时 NTP 同步不上、
   `now()` 不变、时钟分支根本不执行，角标就永远画不出来。
7. 离线时跳过 `getCityCode()` / `getCityWeater()`，避免开机硬闯网络卡住。

### 附带新功能：OLED「今日总时长」

- 上位机在 UDP 报文里可选增加 `today` 字段（今日所有已添加程序累计秒数）。
- **没有已添加程序在运行时**，OLED 顶行由 `NO GAME` 改为 `TODAY TOTAL`，大字显示今日合计。
- 网页新增「游戏时长 OLED」卡片，开关可关闭（存 EEPROM `247` 标志 / `248` 值，默认开）。
- 兼容旧版上位机：**只有真的收到过 `today` 才显示** `TODAY TOTAL`，
  否则仍是 `NO GAME`，不会误报 `00:00:00`。

### 网页新增

- **「网络」卡片**：状态 / SSID / IP / 信号强度 + 「重新配网」「忘记网络」两个按钮。
- **「游戏时长 OLED」卡片**：今日总时长显示开关。

## V1.6.7 修复：屏幕不亮（背光引脚定义在错误的文件里）+ 极性可运行时切换

### 现象

BLK 从 3.3V 改接到 GPIO33 后，**屏幕完全不亮**，接线检查无误。

### 根因（读代码看不出来，要摸环境）

同一台电脑上存在**两份** TFT_eSPI：

| 位置 | 版本 | 是否被编译使用 |
|---|---|---|
| `D:\Downloads\V1.4\libraries\TFT_eSPI` | 2.3.58 | ❌ **不用** |
| `D:\Users\Evan\Documents\Arduino\libraries\TFT_eSPI` | 2.5.43 | ✅ **实际用它** |

Arduino IDE 用的是 **sketchbook 下的库**，项目里那份 `libraries/` 只是过期快照。
之前把 `#define TFT_BL 33` 写进了**项目内那份**，于是：

```
TFT_BL 未定义 → LCD_BL_PIN 退化成 -1
              → initLCDBacklight()/setLCDBacklight() 第一行就 return
              → GPIO33 从未被配置成输出（悬空）
              → 背光恒灭 = 黑屏
```

**软件通道（EEPROM/串口/网页滑块）全都是通的，唯独输出脚没人驱动**——所以现象是"改什么都没用"。

### 修复

1. **背光引脚改由固件自己定义**（`.ino` 里的 `LCD_BL_PIN_DEFAULT = 33`），
   不再依赖任何 `User_Setup.h`。无论用哪份库、哪个 core，GPIO33 都会被正常驱动。
   项目内库那份的 `#define TFT_BL 33` 已**撤掉**并留注释说明，避免两个来源。
2. **极性改为运行时可切换**：新增 EEPROM `245`（标志 `0x5A`）/ `246`（值），
   网页「显示」卡加了分段开关，`/dbg` 也会显示。
   默认 **高电平点亮（直驱）**，因为"把 BLK 直接挪到 GPIO33"是最常见接法。
3. **新增串口自救通道**：串口监视器发一个字母 **`p`** 即可切换极性（并把亮度设为 100%）。
   黑屏时屏幕看不见，但串口和网页都能用，不必重刷固件。

### 接线极性对照

| BLK 接法 | 极性选项 |
|---|---|
| **直连 GPIO33**（背光电流 ≤ 8mA 才推荐） | **高电平点亮**（默认） |
| 经 **P-MOSFET(AO3401) / PNP(S8550) 高边开关**，栅极经 1k 接 GPIO33，另加 10k 上拉到 3.3V | **低电平点亮** |

选错的表现是「亮度越大越暗」，100% 时黑屏。改一处选项即可，不用改代码。

> 为什么只能是高边开关：BLK 原来接 3.3V 才亮，说明它是背光 LED 的**阳极**馈电脚；
> LED 阴极在模块内部直接接地，动不了，所以开关只能串在「3.3V → BLK」之间。

## V1.6.6 时钟数字描边（方案A）+ 亮度定时

### 一、时钟数字描边

#### 为什么不能沿用「文字描边」

已经做好的「文字描边」是在 sprite 上把 `drawString()` 画 9 次偏移 —— 那是**矢量字体**的做法。
而时钟数字是 **JPEG 位图字模**（`W_3660_i*` 36×60、`W_1830_i*` 18×30），走的是
`number.cpp` → `TJpgDec.drawJpg()` → 解码回调里"透明键控 + 动态着色"，**八方向偏移完全用不上**。

而且原来那套着色是**单点斜坡**（`lum=0→黑`、`lum=255→目标色`），本质只能表达**一种颜色**，
没法同时给出"描边色"和"笔画色"。

#### 方案：2bpp 掩膜 + 运行时合成

把字模重做成 **4 级掩膜**，描边成为独立的一级：

| 掩膜级别 | 含义 | 绘制结果 |
|---|---|---|
| 0 | 透明 | 直接取 `bgBuff` 的背景像素（透明键控） |
| 1 | 描边过渡 | 描边色按 55% 与背景混合（外缘不硬） |
| 2 | 描边实心 | 描边色 |
| 3 | 笔画 | 笔画色 |

生成方式（`tools/gen_digit_mask.py`）：源字模本身就是**严格两极**（52.4% 纯黑 + 47.6% 纯白，
过渡带 0%），所以可以干净二值化 → 形态学**圆盘**膨胀 → 得到描边环 → 打包 2bpp。
掩膜会向外留出描边余量（PAD），绘制时按 `(x-PAD, y-PAD)` 贴，**视觉位置不变**。

描边厚度（大字笔画约 8px、小字约 4px，按比例取）：

| 字号 | 描边 | 掩膜尺寸 | 每字 | 10 字 |
|---|---|---|---|---|
| 36×60 | 1px 实心 + 1px 过渡（≈1.5px） | 40×64 | 640 B | 6.4 KB |
| 18×30 | 1px 实心（≈1.0px） | 20×32 | 160 B | 1.6 KB |

**合计 7.8 KB**，而原来那套 JPEG 字模约 28 KB（源文件 320KB）→ **flash 净减约 20KB**，
而且**省掉了每秒 6 次的 JPEG 解码**。

#### 三个可独立控制的开关（都属于当前壁纸）

| 控件 | 说明 |
|---|---|
| **数字描边** | 独立开关，与「文字描边」互不影响（两套机制） |
| **描边自动取反** | 开：**亮字配黑边、暗字配白边**（按笔画色亮度取反，随配色自动变）。关：用下面选的固定色 |
| **数字描边色** | 仅在"自动取反"关闭时生效 |

预设里的存储：`flags` 新增 `PF_NUMOUTLINE(0x08)`；"自动取反"用 **取反语义**（`PF_NUMOUTFIX(0x10)`，
置位=用固定色）—— 这样**旧版预设升级后自动落到"自动取反"**，符合直觉；
固定色存进原来空着的 `P_NUMOC`（第 14/15 字节）。

#### 顺带清理

`O_3660_i*`（橙色字模，源文件 188KB）**从来没有任何调用**（`printfO3660` 是死代码），

## V1.6.5 屏幕亮度可调（背光接 GPIO + PWM）

### 之前为什么调不了

软件其实**早就写好了**：`initLCDBacklight()` / `setLCDBacklight()`（LEDC PWM 5kHz / 10bit）、EEPROM `BL_addr`、串口命令 `0x01`、配网门户参数 `LCDBL`（还会持久化）。**卡在硬件**：

`User_Setup.h` 里 `TFT_BL` 是注释掉的 → `LCD_BL_PIN = -1` → 两个函数第一行就 `return`，所有软件通道全部空转。

> 一个必须注意的细节：TFT_eSPI 只在 `#if defined(TFT_BL) && defined(TFT_BACKLIGHT_ON)` 时才接管这个脚。所以启用时**只定义 `TFT_BL`，绝对不要定义 `TFT_BACKLIGHT_ON`** —— 否则 TFT_eSPI 会在 `begin()` 里把该脚设成普通 GPIO 输出，抢掉我们的 LEDC 配置，结果就是"只能全亮或全灭，调不了亮度"。

### 硬件：为什么必须是"高边开关"

BLK 原来是**接 3.3V 才亮的**，这就说明 **BLK 是背光 LED 的阳极馈电脚**（反向接 3.3V 不可能点亮）。LED 阴极在模块内部直接接地，动不了。所以要调光只能在「3.3V → BLK」之间串开关：

```
3.3V ──[P-MOSFET(高边开关)]── BLK ──[模块内限流R]──[LED]── GND
                    │
                 GPIO33 (PWM)
```

- 器件：P-MOSFET（AO3401）或 PNP（S8550）。S/E 接 3.3V，D/C 接 BLK，G/B 经 1k 接 GPIO33，**并加 10k 上拉到 3.3V 防上电乱亮**
- **反逻辑**：GPIO 越低越亮 → 代码里占空比取反（`LCD_BL_ACTIVE_LOW 1`）
- 空闲 GPIO 可选 **33 / 32 / 26 / 19 / 17 / 16**（避开 strapping：0=boot、2=strap、12=MTDI、15=MTDO）；已占用：23/18/5/27/4（TFT）、21/22（I2C）、25（触摸）
- 如果实测背光电流 **≤ 8mA**，也可以把 BLK 直接接 GPIO33（无开关、正逻辑，`LCD_BL_ACTIVE_LOW 0`）。但多数 1.3" 模块是 15~25mA，**超出 ESP32 引脚推荐值（12mA）**，所以默认按高边开关配置

### ★ 顺手堵掉一个会黑屏的坑

旧代码读亮度是：

```cpp
if(EEPROM.read(BL_addr) <= 100) LCD_BL_PWM = EEPROM.read(BL_addr);
```

而**本机 EEPROM 未写过的字节读出来是 `0x00`**（V1.6.3 已实测确证），`0x00 <= 100` 成立 → 得到"亮度 = 0"。以前 `TFT_BL` 没定义所以看不出来；**一旦接上背光调光，这就是开机黑屏**。

修复：新增 EEPROM 222 = `BLValid_addr` 作为"已写过"标志（`0x5A`），区分"真的设成 0"和"从来没写过"；未写过时默认 100%（与原来直连 3.3V 的观感一致）。同时亮度下限夹在 5%（0 不再可设），避免误设成 0 后黑屏难恢复。

### 软件侧改动（共 5 处）

| 位置 | 改动 |
|---|---|
| `User_Setup.h` | `#define TFT_BL 33`（不定义 `TFT_BACKLIGHT_ON`） |
| `.ino` 背光常量区 | 新增 `LCD_BL_ACTIVE_LOW`（高边开关=1 / 直驱=0）、`LCD_BL_MIN 5` |
| `setLCDBacklight()` | 反逻辑时占空比取反 |
| setup / 门户 / `handleSave` | 亮度读写统一带 `BLValid` 标志 |
| 网页「显示」卡 | **亮度滑块回归**（V1.5.1 因硬件不支持移除，现在有意义了），5%~100%，保存即时生效、断电保持 |

`/dbg` 诊断页也加了背光行：`引脚 / 亮度 / 极性 / BLValid / BL原始值`，方便确认接线与极性是否匹配。

### 验证

- PWM 映射核对（反逻辑）：亮度 5%→`ledcWrite` 972、50%→512、100%→0，单调正确，边界正确
- 主页 `<div>` 39/39、`/dbg` 全部标签平衡、两个 `<script>` 块语法通过
- 编译 1,361,574 bytes（43%），全局变量 106,008（32%），余 221,672，**0 error 0 warning**

### 烧录与接线顺序

1. 先烧 V1.6.5（此时 GPIO33 在输出 PWM，但**没接东西，无副作用**）
2. 按上图把 BLK 从 3.3V 改接到开关，再从开关接 3.3V
3. 通电，屏幕应亮（默认 100%）；打开网页拖「屏幕亮度」滑块，应立即变化
4. 若发现**滑块越大越暗**，说明你用的是正逻辑（直驱或无开关），把 `LCD_BL_ACTIVE_LOW` 改成 `0` 即可

## V1.6.4 修复：温湿度图标擦掉了指示条 / 切背景时天气要等网络

### 问题一：左下角温湿度图标把指示条削掉一块

**现象**：左下角两个温湿度图标（x=15）右侧"覆盖太大"，把 45~96 处的**条状温湿度指示条**盖掉左半截。

**根因**：`drawIconWithBg()` 里恢复背景用的矩形是**写死的 60×60**：

```cpp
int16_t w = 60, h = 60;      // ← 旧代码，"图标尺寸未知，保守起见按 60x60"
bgDrawRegion(x, y, w, h);
```

而 `temperature.h` / `humidity.h` 的真实尺寸只有 **24×24**（直接从 JPEG 头的 SOFn 段读出来的）。于是还原框从 x=15 一直盖到 x=74，与两条指示条重叠：

| 元素 | 位置 | 与旧还原框(15..74)重叠宽度 |
|---|---|---|
| 温度条 `tempWin()` | (45,192) 52×6 | **30 像素**（52 像素被削掉 58%） |
| 湿度条 `humidityWin()` | (45,222) 52×6 | **30 像素** |

**为什么开机时看不出来、只有切背景才出现** —— 绘制顺序不同：

| 时机 | 顺序 | 结果 |
|---|---|---|
| 开机 `setup()` | `drawBg()` → 画图标 → `getCityWeater()`（画天气含指示条） | 图标在前，条后画 ✓ 正常 |
| 切背景 `refreshAfterBgChange()` | `drawBg()` → `LCD_reflash(1)`（画天气含指示条）→ **画图标** | 图标在后，把条削掉 ✗ |

**修复**：`drawIconWithBg()` 改为**从 JPEG 头读出真实宽高**（新增 `jpegSizeOf()`，扫描 SOF0~SOF15 段，排除 DHT/JPG/DAC），只还原图标自身范围。解析失败才退回 60×60。这样以后换任何尺寸的图标都不会再出这个问题。

```cpp
int16_t w = 0, h = 0;
if (!jpegSizeOf(icon, iconSize, &w, &h)) { w = 60; h = 60; }
```

实测：`temperature`/`humidity` → `24x24` ✓，天气图标 `t0`/`t11` → `60x60` ✓。

### 问题二：切换背景刷新时，天气部分要等很久才显示

**根因**：`refreshAfterBgChange()` 调用 `LCD_reflash(1)`，而 `LCD_reflash` 里 `en == 1` 会**强制走一次阻塞式 `getCityWeater()`**：

```cpp
if(millis() - weaterTime > (60000*updateweater_time) || en == 1 || ...) {
    getCityWeater();     // ← DNS + 连接 + 响应，慢的时候好几秒
}
```

而 `getCityWeater()` 内部才调 `weaterData()` 去**解析并绘制**天气区。所以天气区必须等网络请求跑完才出现 —— 就是"偶尔非常慢"。（天气接口偶发慢/失败时，天气区甚至会一直空着。）

**修复**：把「抓取/解析」与「绘制」彻底分开。

1. 新增缓存变量 `wxTempS / wxSDS / wxCityS / wxAqiTxt / wxAqiCol / wxCode / wxValid`
2. `weaterData()` 只做**解析 → 存缓存 + 存滚动文本**，然后调 `drawWeather()`
3. 抽出 `drawWeather()`：**只读缓存绘制**整个天气区（室外温湿度 + 两条指示条、城市名、AQI 徽章、天气图标）
4. `LCD_reflash(int en, bool allowFetch = true)` 新增参数把两件事解耦：
   - 只有"到点该更新了 / 用户主动要求更新"才联网
   - `en == 1`（整屏重绘）不再顺带联网，末尾改为 `if (en == 1 && !wxFresh) drawWeather();`
5. `refreshAfterBgChange()` 用 `LCD_reflash(1, !wxValid)` —— 已有天气数据时不联网；还没有任何数据时才允许兜底抓一次

**效果**：切背景时天气区**立即**用缓存重画（0 网络开销），不再卡几秒。附带好处：网络失败时天气区不会变空白，仍保留上一次的数据。

> 注意 `en == 1` 仍必须**补画**天气区：`drawBg()` 会把整屏背景重铺一遍，天气文字/图标/指示条都被盖掉，不补画就要等到下一次天气更新（最多 `updateweater_time` 分钟）才恢复。

### 顺带说明：为什么这两件事要一起修

问题二修好后，切背景时天气区会被**立即重画**（含指示条），紧接着才画 DHT 图标 —— 也就是说问题一的绘制顺序会**稳定复现**。所以必须同时修好还原矩形，否则问题一会更明显。

## V1.6.3 修复：换壁纸后「除温湿度外全部变纯黑」的真正根因

### 现象

切换壁纸时，**小时/分钟/秒钟/日期城市/滚动条 4 组配色全部变成 `#000000` 纯黑**，只有**室内温湿度**那一组保持正常。第 1 张壁纸不受影响。

> 这一条是 V1.6.2 没修好的那次 —— 用户反馈"还是不行，除了温湿度全恢复成 r0g0b0，就第一个背景不会恢复"。

### 定位过程（这次没有靠猜）

设备在局域网里可以直接访问，于是**直接用 HTTP 把设备内部状态读出来**，拿到了硬证据：

```bash
curl http://192.168.5.86/            # 网页里就带着 5 个取色器的当前值
curl "http://192.168.5.86/setbg?slot=N"   # 逐个槽位切换后再读
```

逐槽位实测结果（`http://<ip>/setbg?slot=N` → 再读 `/`）：

| 槽位 | 小时 | 分钟 | 秒钟 | 日期 | 温湿度 | 暗化 | 开关 |
|---|---|---|---|---|---|---|---|
| 1 | `#FF0000` | `#00FFFF` | `#00FFFF` | `#00FFFF` | `#8400FF` | 100% | 05 |
| 2 | **`#000000`** | **`#000000`** | **`#000000`** | **`#000000`** | `#0000FF` | 100% | 05 |
| 3 | **`#000000`** | **`#000000`** | **`#000000`** | **`#000000`** | `#8400FF` | 100% | 07 |
| 4 | **`#000000`** | **`#000000`** | **`#000000`** | **`#000000`** | `#7BFFB5` | 84% | 05 |
| 5 | **`#000000`** | **`#000000`** | **`#000000`** | **`#000000`** | `#FF7D00` | 86% | 05 |

**模式非常干净**：每个槽位的 **offset 8~11（温湿度色 / 暗化 / 开关）都是对的且各不相同**，只有 **offset 0~7（时分秒+日期四色）是零**。

### 根因

顺着这条线索反推，指向同一个事实：

> **本机 EEPROM 里"从未被写过"的字节读出来是 `0x00`，而不是 `0xFF`。**

验证方法：`bgVer`（EEPROM 216~220）从来没有被任何代码写入过，而网页缩略图显示 `v=0` —— 代码逻辑是"读到 `0xFF` 才改判成 1"，读到 `0` 说明实际值就是 `0x00`。

由此产生连环故障：

1. **`readColor16()` 只把 `0xFF,0xFF` 当"未初始化"** → `0x00,0x00` 被当成"用户设的纯黑"
2. **`presetMask = EEPROM.read(132) & 0x1F`**，读到 `0xFF` 时得到 **`0x1F`** → **五个槽位全被认定为"已有预设"**
3. 于是 `loadPreset()` 走"原样读"分支，把**从未写过的槽位读出 `0x0000`** → 全局配色被写成纯黑
4. 紧接着 `savePreset()` 又把这份黑配色**落盘到各个槽位** → 每张壁纸都留下"4 黑 + 自己的温湿度色"

第 1 张壁纸之所以没事，是因为用户是在它上面**完整设过 5 个颜色**的。

### 修复

三个层次一起堵：

1. **预设记录加"魔数 + 校验"（核心）** —— 有效性必须靠**写入时留下的正向标记**，绝不能用"擦除值"来判断：
   ```cpp
   #define P_MAGIC  12        // 0xA5
   #define P_CHK    13        // 前 12 字节求和后取反
   #define PRESET_MAGIC 0xA5
   ```
   `loadPreset()` 只认魔数+校验都通过的记录；**无效就"继承当前观感"，绝不加载**。
   `presetMask` 降级为仅供 `/dbg` 展示，不再参与判断。
   写序也不能反：**先写校验、再写魔数** —— 中途掉电只会得到"无效记录"，不会得到"假的有效记录"。

2. **未初始化检测同时认 `0x00` 和 `0xFF`** —— `colorAddrUnwritten()`：
   ```cpp
   return (lo == 0x00 && hi == 0x00) || (lo == 0xFF && hi == 0xFF);
   ```
   全局配色首次启动若发现标志缺失，立即写入默认值并落盘，之后都走确定路径。

3. **网页传来的颜色串必须校验格式** —— `validHexColor()`（必须是 `#RRGGBB`，7 字符）。
   > 为什么这个也要加：`hexToColor("")` 会返回 `0x0000`（`strtol` 解析空串得 0）。只要字段缺失/为空/格式不对，"保存"就会把配色**静默改成纯黑**，再被 `savePreset` 传染到每一张壁纸。**宁可保持原值，也不要改成黑色。**

### 顺带修掉的两个真 bug

- **`setColorValue()` / `outlineColorFor()` / `bgFillSprite()` 的字节序错误**：全局配色存的是**自然序** RGB565（实测：写入 `#112233`，读回 `#102031`，正是自然序展开），但这三处都先把颜色当成"交换序"又交换了一次，导致**「自动换色」算出来的色相全错**。`tft_output` 里 `tintTarget` 是按自然序解码的，两处必须一致。
- **`loadBgVersions()` 只判 `0xFF`**：版本号永远是 0，缩略图 URL 不随图片变化（缓存标记失效）。同时改成 `0x00` 也算未写过，并把推导值落盘。

## V1.6.2 修复：白色配色存不住 / 换壁纸后别的壁纸配色被改掉

### 现象

保存某张壁纸的预设后，切到别的壁纸再切回来，**原来那张壁纸的配色被改掉了**（变成了另一张壁纸的颜色）。

### 根因：`0xFFFF` 既当"未初始化"哨兵、又是白色本身

原来读 16bit 颜色的函数用 `0xFFFF` 判断"这个地址还没写过"：

```cpp
static uint16_t readColor16(int addr, uint16_t defVal)
{
  uint8_t lo = EEPROM.read(addr);
  uint8_t hi = EEPROM.read(addr + 1);
  if (lo == 0xFF && hi == 0xFF) return defVal;   // ← 白色正好是 0xFFFF！
  return lo | (hi << 8);
}
```

而 **RGB565 的白色就是 `0xFFFF`**，并且白色正是时分秒 / 普通文字 / 温湿度的**默认配色**。于是：

1. 壁纸 1 用默认白色，保存 → 预设里存的是 `FF FF`
2. 切到壁纸 2，把小时改成绿色、秒钟改成红色，保存
3. 切回壁纸 1 → 读预设时遇到 `FF FF` → **判为"未初始化"→ 回落到"当前值"**，也就是壁纸 2 的颜色
4. 结果：壁纸 1 的白色时钟不见了，变成了壁纸 2 的绿/红

只要某个颜色是**白色**，它就永远存不住。这个问题在全局配色上也存在，只是因为全局读取时传入的"默认值"恰好也是白色，所以**看不出来**；一旦涉及跨壁纸切换（默认值变成"当前值"），立刻暴露。

### 修复

**① 预设读取改为"原样读"，不再判断未初始化**

槽位是否有效，本来就由 `presetMask` 的对应位保证了，不需要再靠哨兵值判断：

```cpp
static uint16_t readColor16Raw(int addr)   // 新增：原样读
{
  return (uint16_t)EEPROM.read(addr) | ((uint16_t)EEPROM.read(addr + 1) << 8);
}
// loadPreset 里改用 readColor16Raw()
```

> 这同时**修好了已有数据**：旧版存的 `FF FF` 本来就是"白色"的正确编码，原样读出来正好是白色。

**② 全局配色改用独立的"已写入"标志**

新增 EEPROM 地址 221：`0x5A` 表示全局配色已写过。写过之后一律原样读；没写过（老数据 / 首次）则沿用原来的哨兵逻辑，保证升级兼容。

这样「把分钟颜色设成白色」也能在重启后保持了（原来会变回默认橙色）。

### 验证方式

把预设读写逻辑用 Python **1:1 搬到电脑上跑**（用 1024 字节数组模拟 EEPROM），完整走一遍「壁纸1保存 → 切壁纸2 → 改色保存 → 切回壁纸1」，直接复现了故障，修复后同一场景全部通过。

> 这类"逻辑正确但数据编码撞车"的 Bug，光读代码很难看出来，**用主机端模拟跑一遍是最快的定位手段**。

### EEPROM 地址（V1.6.2 新增）

| 地址 | 用途 |
|---|---|
| 216~220 | 各槽位图片版本号（缩略图缓存标记，V1.6.1） |
| 221 | 全局配色"已写入"标志（`0x5A`） |

地址布局已核验零冲突，最高用到 221，余量 803 字节。

## V1.6.1 网页加载/保存变快

### 原因（三个真凶）

**① 缩略图每次刷新都重新下载（主因）**

网页里缩略图的 URL 用了 `millis()` 当缓存标记：

```cpp
h += "<img src='/preview?slot=" + String(i) + "&t=" + String(millis()) + "'>";
```

`millis()` **每次生成页面都不同** → 浏览器认为图片变了 → **每次刷新都重新下载全部 5 张 240×240 原图**（每张约 20~30KB，合计约 100~150KB），而缩略图显示尺寸只有几十像素。

修复：改用**每槽位的图片版本号**做缓存标记。

- 新增 EEPROM 地址 216~220：5 个槽位各 1 字节版本号
- 上传/删除图片时 `bgBumpVer(slot)` 自增 → URL 变化 → 浏览器才重新拉取
- `handlePreview` 加上 `Cache-Control: public, max-age=604800` 与 `ETag`
- **效果：图片没变时缩略图走浏览器缓存，不再产生任何流量；换图时只有那一张重新下载**

**② 页面 HTML 里内联了 15 个色块 × 5 处**

服务端为每个取色器输出 15 个色块，共 7,714 字节，占整页 37%。

修复：服务端只输出**空的 `.sw` 容器**，色块由浏览器 JS 生成（调色板 `PAL` 数组 + `buildSw()`，用事件委托处理点击）。

| | 页面体积 |
|---|---|
| V1.6 | 20,991 字节 |
| **V1.6.1** | **14,940 字节（-29%）** |

> 顺带把选色块的 `onclick` 内联写法换成**事件委托**，生成的 HTML 更短、转义也更简单。
> ⚠️ 调色板现在定义在网页 JS 里的 `PAL` 变量，改色块请改那里。

**③ 保存/切换/删除后，浏览器要等整屏重绘完才收到跳转**

原代码是「先重绘，后响应」：


体感就是「点保存后卡很久才回到页面」。

## V1.6 文字清晰度增强 + 每张壁纸独立预设 + 自动循环

### 1. 三个文字清晰度增强功能（每张壁纸可独立开关）

| 功能 | 原理 | 适用范围 |
|---|---|---|
| **自动换色** | 按区域背景亮度决定文字明暗：背景亮→转深色字，背景暗→转浅色字。**保留用户选定的色相与饱和度**，只改明度 | 全部（含时钟数字） |
| **自适应底板** | 把文字背后的背景按需压暗/提亮，使与文字的亮度差 ≥ 110/255。**不是纯黑框，背景内容仍可见** | 矢量文字（日期/城市/温湿度/滚动条）；时钟数字不适用（会变成矩形黑框） |
| **文字描边** | 矢量文字八方向描边，描边色自动取反（亮字配黑边、暗字配白边） | 仅矢量文字（数字是图片字模） |

**关键实现细节：**

```cpp
// 自动换色：等比缩放各分量 => R:G:B 比例不变 => 色相与饱和度不变，只改明度
uint32_t k = ((uint32_t)targetV << 8) / maxChannel;   // 最大分量正好落到 targetV
r = (r * k) >> 8;  g = (g * k) >> 8;  b = (b * k) >> 8;

// 明暗档：深色档明度 62/255，浅色档 238/255
// 滞回：浅色→深色 需背景亮度 > 150；深色→浅色 需 < 120（防止阈值附近字色来回跳）
```

**为什么必须做滞回**：没有滞回时，背景亮度在阈值附近波动会让文字颜色反复切换，非常刺眼。实测序列 `[100,130,140,155,160,145,130,115,105]` 在滞回下只在 155 处切换一次、115 处回退一次；无滞回则会在 130/140 之间反复抖动。

**底板强度**：全局滑块 0~100%。默认 **100%**，此时恰好达到对比度目标；调低则减弱效果。
> 注意：强度是「向目标推进的比例」。若默认给 70%，在亮背景上会达不到目标（实测背景亮度 200 时只差 89 < 110），故默认改为 100%。

**区域亮度统计**：在 `drawBg()` 之后扫两遍 `bgBuff`，统计两个区域的平均亮度：
- 时钟区域 `x 15~224, y 78~145`
- 文字区域 `x 5~235, y 12~76` 与 `y 146~238`（避开时钟带）

采样步长 2，约 3 万次循环，开销可忽略。换壁纸时做一次「硬判定」（直接把滞回状态设为 `亮度 > 150`），之后靠滞回保持稳定。

### 2. 每张壁纸独立预设

每张壁纸保存一套完整的显示参数，**切换壁纸时自动切换**：

```
每个槽位 16 字节（EEPROM 136~215）：
  +0..1   小时色        +6..7  日期/城市/滚动条色
  +2..3   分钟色        +8..9  室内温湿度色
```

- 切换壁纸（触摸 / 网页 / 自动循环）时：先把当前观感**存回原槽位**，再**载入新槽位**的预设

## V1.5.5 三项改动

### 1. 修复「贴片区能显示背景但仍偏黑」——8bpp 量化改最近值舍入

**现象**：黑框已消失、背景能透出，但文字框 / 数字框区域比屏幕其余背景明显偏暗，背景图越暗越明显。

**根因**：贴片区取的是 8bpp（RGB332）背景缓存，而屏幕其余区域是 16bpp，两者色深不同。原 8bpp 编解码用**截断**（`r5>>2` / `g6>>3` / `b5>>3`），解码时又用 `(x<<2)|(x>>1)` 补低位，使：
- 前两个量化档的重建点落在档中心**下方**约 1.5 级（5bit 计）
- 最暗档 `r5=1..3` 直接塌成 **0（纯黑）**

真实图片暗部像素占比高，于是整体净向暗偏 + 暗部细节丢失。

实测（同一张 240×240 背景，逐像素比对 16bpp 屏幕与 8bpp 贴片区）：

| 背景类型 | 平均偏移 | 明显更暗(<−8) | 压成纯黑 |
|---|---|---|---|
| 明亮照片 | +4.3 | 11.0% | 0% |
| 深色图 | −0.4 | 5.7% | 2.4% |
| **暗色调** | **−10.3** | **63.8%** | **14.6%** |

**修复**：改为**最近值舍入**（重建点回到档中心）

```cpp
// 编码 5/6/5bit -> 3/3/2bit
r3 = (r5 * 7 + 15) / 31;   g3 = (g6 * 7 + 31) / 63;   b2 = (b5 * 3 + 15) / 31;
// 解码 3/3/2bit -> 5/6/5bit
r5 = (r3 * 31 + 3) / 7;    g6 = (g3 * 63 + 3) / 7;    b5 = (b2 * 31 + 1) / 3;
```

全量遍历 32×64×32 组合验证：R/G/B 最大误差 **2 / 4 / 5**，均已达该位宽的理论下限。同一张暗色调背景实测：

| 指标 | 修改前 | 修改后 |
|---|---|---|
| 平均偏移 | −10.25 | **−1.23** |
| 压成纯黑像素 | 14.6% | **3.0%** |
| 明显更暗像素 | 63.8% | **16.7%** |

> 曾评估「Bayer 有序抖动」方案，实测反而更差（暗部偏移 −10.25 → −12.95，压成纯黑 14.6% → 20.2%），已排除。

**排查中排除的三个嫌疑**（记录备查，都不是原因）：
- 回调坐标正确：`TJpg_Decoder.cpp` 里 `x = jrect->left + jpeg_x`，是**绝对屏幕坐标**
- 白色数字字模亮度**严格两极**（52.4% 纯黑 + 47.6% 纯白，过渡带 0%），不存在抗锯齿暗边
- 图标框内平均亮度实测只比纯背景差 ±4，可忽略

## V1.5.4 修复：文字/数字黑框的真正根因（背景缓存内存不足）

### 现象（用户反馈）

有背景图时，**所有文字**（城市名、空气质量、温湿度、日期星期、滚动字幕）以及**时钟数字、图标**都出现**规整矩形、边界清晰的黑框**；无背景图时一切正常。

### 真根因（已由链接器实测确认）

原方案用一个 **240×240 × 16bpp = 115,200 字节** 的 `TFT_eSprite` 缓存背景：

```cpp
bgCanvas.createSprite(BG_WIDTH, BG_HEIGHT);   // 需要一整块 115KB 连续内存
```

但本板 ESP32 的 DRAM **极其紧张**。实测证据：把这块缓存改成同尺寸的**静态数组**后，链接直接报错——

```
section `.dram0.bss' will not fit in region `dram0_0_seg'
region `dram0_0_seg' overflowed by 39256 bytes
```

即：**DRAM 只剩约 76KB 可用，根本装不下 115KB**。于是 `createSprite()` 必然返回 `nullptr`：

- `bgCanvasReady = false`
- **所有文字 sprite** 走 `fillSprite(0x0000)` → 整片纯黑矩形 = 用户看到的「文字黑框」
- **数字/图标键控**条件含 `bgCanvasReady` → 透明键控全部失效 = 「数字黑框」

**一个原因解释了全部现象**（这也是为什么 V1.5.1 改 8bpp、V1.5.3 加键控都没能真正修好——它们都建立在「背景缓存存在」这个错误前提上）。

### 解决方案：改用静态 8bpp（RGB332）背景缓存

不再要 115KB，改为 **240×240 × 1 字节 = 57,600 字节** 的全局静态数组，存 **RGB332**：

```cpp
uint8_t bgBuff[BG_WIDTH * BG_HEIGHT];   // 57,600 字节，链接期预留，永不失败
```

- 读取时按需把 RGB332 展开成「交换序 RGB565」，与字模 / 屏幕同格式直接互换；
- 背景是装饰性内容，8bpp 足够（纯色往返误差 0，渐变最大误差约 58/255，肉眼几乎无差）；
- 静态分配由链接器在启动时预留，**任何情况下都不会失败**。

**实测内存**（`PartitionScheme=huge_app`）：

| 方案 | 需要 | 结果 |
|---|---|---|
| 16bpp 静态缓冲 | 115,200 字节 | ❌ `dram0_0_seg` 溢出 39,256 字节 |
| **8bpp 静态缓冲** | **57,600 字节** | ✅ 全局变量 105,856 / 327,680（32%），剩余 221,824 |

### 涉及的三条读取路径（全部改为从 `bgBuff` 展开）

| 路径 | 用途 | 实现 |
|---|---|---|
| `bgFillSprite()` | 文字 sprite 先贴底 | 逐行 `bg332to565sw(bgBuff[...])` 写入 sprite buffer |
| `tft_output()` | 字模/图标透明键控 | 亮度 < 48 的像素改填 `bg332to565sw(bgBuff[...])` |
| `bgDrawRegion()` | 图标区域还原背景 | 逐行展开后 `tft.pushImage` 到屏幕 |

写入路径 `tft_output_bg()` 在把像素推给屏幕的同时，用 `bg565to332()` 降采样存入 `bgBuff`。

### 颜色转换函数（RGB332 标准布局 RRRGGGBB）

```cpp
static inline uint8_t  bg565to332(uint16_t swapped);    // 565(交换序) -> 332
static inline uint16_t bg332to565sw(uint8_t p);         // 332 -> 565(交换序)
```

> 注意：565→332 时 R 取高 3 位、G 取高 3 位、B 取高 2 位；332→565 时低位用高位补齐，保持亮度。

## V1.5.3 修复：字模黑框（透明键控）

> ⚠️ **本节只是「数字/图标黑框」的部分修复，不是完整方案。**
> 用户在 V1.5.3 后仍反馈黑框存在——真正原因是背景缓存内存分配失败，
> 见上方 **V1.5.4**。本节介绍的透明键控逻辑保留有效（它解决的是
> 「JPEG 字模无 alpha 通道」这一层问题），但前提是背景缓存真的可用。

### 现象

有背景图时，时钟数字、温湿度图标等区域的背景图被**黑色矩形**挡住（无背景图时黑底看不出来，所以只在有背景图时可见）。

### 根因

这些图形是 **JPEG 格式的字模/图标**，JPEG **没有 alpha 透明通道**，其"透明区域"实际就是**纯黑像素**。实测数据：

| 资源 | 尺寸 | 纯黑像素占比 |
|---|---|---|
| `W_3660_i0`（数字"0"） | 36×60 | **52.4%** |
| `W_1830_i0`（小数字） | 18×30 | 52.4% |
| `temperature`（温度图标） | 24×24 | **84.5%** |
| `humidity`（湿度图标） | 24×24 | 73.1% |

绘制时回调 `tft_output()` 把整个矩形（含这 52%~84% 的黑像素）**原样 `pushImage` 到屏幕**，于是背景图上被盖出一块块规整黑矩形。

> 注：日期/星期/城市等文字用的是 vlw 平滑字体，绘制在 sprite 里并用 `bgFillSprite()` 贴底，本来就正确；**只有走 `TJpgDec.drawJpg()` 直绘的字模/图标有此问题**。

### 解决方案：透明键控（color key）

在 `tft_output()` 回调里对每个像素按亮度判定：

```
lum = (R×30 + G×59 + B×11) / 100
if (有背景图 && lum < 48)  → 该像素判为"字模黑底"，改为填背景画布对应位置的像素
else                        → 保留（数字笔画，继续走动态着色）
```

阈值取 **48**：实测字模亮度呈两极分布（黑底集中在 0~15，笔画在 240~255），48 落在安全空档，**抗锯齿边缘完整保留**（验证：保留像素最低亮度 249）。

同一处修复同时解决了**温湿度图标**的黑框（它们也走 `tft_output`）。

### 关键实现细节

**字节序必须自洽**。背景画布 `bgCanvas` 是 16bpp sprite，`setSwapBytes(false)` → 存入的是**与 TJpgDec 输出一致的"交换序"**；而 `bitmap` 也是交换序，两者**同格式可直接互换**，无需额外字节操作。

（注意：sprite 的 `pushSprite()` 会强制 `_tft->setSwapBytes(false)` 后直发原始字节，所以 sprite buffer 存的必须就是这种交换序 —— 这是全链路自洽的前提。）

### 可调参数

```cpp
#define TINT_KEY_THRESHOLD  48   // 黑底判定阈值，调高会吞掉更多暗部笔画
bool tft_output_keying = true;   // 键控总开关（仅在 bgCount>0 && bgCanvasReady 时生效）
```

> 若某图标本身有需要保留的深色部分，可调低阈值（如 24）；若背景仍残留黑边，可调高（如 64）。

## V1.5.2 新功能：网页端图片裁剪 + 压缩

上传背景图时，**浏览器会在本地完成裁剪与压缩**，再传给 ESP32。因此不再需要你自己把图片改成 240×240。

### 使用流程

1. 点击某个槽位的「上传」，选择本地图片（JPG / PNG / WebP / GIF 首帧等均可）。
2. 页面弹出**裁剪面板**：图片上有一个正方形选区，拖动它选择要保留的画面范围。
   - **拖动方块**：移动裁剪区域
   - **滚轮 / 双指**：缩放选区大小（也支持 `+` / `−` 按钮）
   - 点「取消」放弃，「确定并上传」开始处理
3. 浏览器把选区按比例缩放到 **240×240**，并用 JPEG 编码，**自动降质**直到体积 ≤ 64KB（通常质量 0.92 即可，约 30KB）。
4. 上传成功后会自动跳回主页并应用为当前背景，弹窗会显示实际压缩后大小。

### 为什么要裁剪成 1:1

屏幕是 240×240 正方形。若不裁剪，非正方形图片会被拉伸变形（人脸变胖、圆形变椭圆）。裁剪面板强制 1:1，保证画面上屏后比例正确。

### 技术要点

| 环节 | 实现 |
|---|---|
| 读取图片 | `FileReader` → `Image`，全在浏览器内存中完成，不上传原图 |
| 裁剪界面 | `<canvas>` 绘制原图 + 半透明遮罩，选区用 `clearRect` 抠出明亮区域 |
| 缩放 | 第二层 240×240 canvas，`drawImage` 带 `imageSmoothingQuality='high'` 保证画质 |
| 压缩 | `toDataURL('image/jpeg', q)` 循环降质：从 q=0.92 起，每轮 −0.07，直到 base64 长度 ≤ 82000 字符或 q ≤ 0.28（最多 12 轮） |
| 上传统一化 | 最终用 `toBlob()` 以 **JPEG** 输出，确保服务端收到的一定是 JPEG 格式 |
| 移动端 | 支持触摸拖动（`touchstart/move/end`，`passive:false` 以允许 `preventDefault`） |

> **注意**：压缩在浏览器端完成，ESP32 收到的已是处理好的 240×240 JPEG，**不消耗单片机算力**。若浏览器过旧（不支持 canvas / toBlob），仍可退回直接上传 JPEG。

## V1.5.1 修复记录

### 1. 修复「文字区域黑框覆盖背景图」

现象：有时钟数字或文字的区域出现黑色方块，把背景图挡住。

根因（两个叠加）：

1. 文字 sprite 原先用 `setColorDepth(8)`（8bpp）。对其 `pushImage()` 推入 16bit 背景数据时，TFT_eSPI 会走 **8bpp 颜色量化分支**（将 16bit 量化到 256 色调色板），量化结果使背景贴片发黑。
2. `setTextColor(fg, bg)` 的第二个参数是**不透明背景色**，传 `0x0000` 会直接在文字后面画黑色方块。

修复：

- 所有文字 sprite 由 `setColorDepth(8)` 改为 `setColorDepth(16)`，避免量化。
- 所有 `setTextColor(fg, bg)` 改为单参数 `setTextColor(fg)`，背景透明。

### 2. 修复「背景图刷新后温湿度小图标消失」

现象：切换 / 上传 / 删除背景图后，温湿度前面的小图标不见了，必须重启才恢复。

根因：背景变更路径先调用 `drawBg()`（内部 `fillScreen` 清屏）再 `LCD_reflash(1)` 重绘文字，但**漏掉了温湿度图标的重绘**。

修复：抽出统一刷新函数，所有背景变更路径（上传完成 / 保存 / 删除 / 设定背景 / 触摸切换等 6 处）改为调用它：

```cpp
void refreshAfterBgChange()
{
  drawBg();
  LCD_reflash(1);
#if DHT_EN
  if (DHT_img_flag != 0)
  {
    drawIconWithBg(15,183,temperature, sizeof(temperature));  // 温度图标
    drawIconWithBg(15,213,humidity, sizeof(humidity));        // 湿度图标
    IndoorTem();
  }
#endif
}
```

### 3. 新增：时钟数字动态着色

- `number.h` 三个绘制方法增加可选参数 `uint16_t color = 0`（0 表示不着色，走原白色字模）。
- `number.cpp` 新增 `drawTinted()`：若传入颜色则 `setTintColor(color)` → 解码 → `clearTint()`。
- `SmallDesktopDisplay.ino` 的 `tft_output()` 解码回调中实现像素重映射（注意 TJpgDec 输出为**字节交换过的 RGB565**，做分量运算前需 `(c<<8)|(c>>8)` 还原，算完再交换回去）。

## 游戏时长显示（OLED）

OLED 顶部小字显示英文进程名，下方大字显示 `HH:MM:SS` 运行时长；无游戏运行或超过 5 秒收不到数据时显示 `NO GAME 00:00:00`。

数据来源：电脑端后台程序（见 `../game-uptime/README.md`）通过局域网 UDP 每秒发送 `{"running":bool,"name":"...","up":秒}`，监听端口由固件中的 `GAME_UDP_PORT`（默认 **5005**）决定，需与电脑端 `config.json` 的 `esp32_port` 一致；`esp32_ip` 填 ESP32 的固定 IP。

ESP32 固定 IP 两种方式任选：

1. 路由器 DHCP 静态绑定（最简单，固件不用改）。
2. 取消 `SmallDesktopDisplay.ino` 顶部 `//#define USE_STATIC_IP` 的注释，并把 `esp32_staticIP / esp32_gateway / esp32_subnet` 改成你的网段。

Wi-Fi 配网、Web 设置、天气、时钟、温湿度和图片动画逻辑均保留。
